# ADBSat-GPU

Performance-portable C++20/Kokkos implementation of the panel-local and global
coefficient kernels from `../ADBSat-PyVersion`.

## Backends

- AMD: Kokkos HIP (`scripts/build_amd.sh`)
- NVIDIA: Kokkos CUDA (`scripts/build_nvidia.sh`)
- CPU baseline/fallback: Kokkos OpenMP (`scripts/build_cpu.sh`)

Kokkos 5.2.2 is pinned by URL and SHA-256. An installed Kokkos package is used
first. Set `-DADBSAT_FETCH_KOKKOS=OFF` for fully offline/system-package builds.

## Implemented scope

- persistent device-resident panel area, normal and centroid data;
- one fused Kokkos panel kernel plus force/moment reduction;
- Newton, Cook, Maxwell, PICLasMaxwell, Schaaf, Sentman, StorchHyp, a
  scalar-mixture DRIA approximation, and single-species CLL (Walker et al. 2014
  closed form as in `calc/coeff_CLL.py`; fit constants default to atomic oxygen);
- optional pressure/shear coefficient copy-back;
- exact BVH-accelerated ray/triangle shadowing on HIP, CUDA or OpenMP;
- CSV/JSON command-line interface, correctness tests and synchronized benchmark.

Not yet parity-complete with the Python application: CLL's six-species mixture
(single-species CLL matches the Python values to 6e-16 on convex Cylinder-Hex meshes),
solar pressure, MAT input/output, per-panel material
properties, and the atmosphere/campaign orchestration remain in Python. DRIA
currently uses mean-gas properties rather than the Python eight-species sum.
These limits are deliberate and explicit: the current library is a tested GPU
compute core, not yet a drop-in replacement for `simulate.py`.

## Build

```bash
./scripts/build_amd.sh       # local AMD/ROCm machine
./scripts/build_cpu.sh       # portable CPU comparison
./scripts/build_nvidia.sh -DKokkos_ARCH_AMPERE80=ON
```

For NVIDIA, choose the matching `Kokkos_ARCH_*` option. Kokkos permits one
device backend per build, so HIP and CUDA use separate build directories.

## CLI

Base columns are `area,nx,ny,nz,cx,cy,cz`. Exact shadowing additionally needs
the nine triangle vertex coordinates `v0x,...,v2z`:

```bash
build-hip/adbsat-cli panels.csv Sentman -1 0 0 20
build-hip/adbsat-cli panels-with-vertices.csv Sentman -1 0 0 20 shadow
build-hip/adbsat-cli panels.csv CLL -1 0 0 1 noshadow alpha_n=0.8 sigma_t=0.9 speed_ratio=7.72 \
    wall_temperature=300 freestream_temperature=961 reference_area=0.0069
```

Optional `KEY=VALUE` arguments set model parameters (see `adbsat-cli` usage).

The result is one JSON object containing backend, timings, `C_D`, `C_L`, `C_Y`,
`Cf_g`, and `Cm_g`. Geometry is copied once by `Solver`; repeated `compute()`
calls keep it on the GPU.

## Validation and performance

```bash
ctest --test-dir build-hip --output-on-failure
build-hip/adbsat-benchmark 1000000 20
```

The benchmark performs five warmups, fences every measured kernel, reports the
median and minimum, and excludes one-time geometry allocation/transfer. See
[`docs/PERFORMANCE.md`](docs/PERFORMANCE.md) for local results and interpretation.

## API sketch

```cpp
Kokkos::ScopeGuard guard(argc, argv);
adbsat::Solver solver(panels);             // one host-to-device transfer
adbsat::Parameters p;
p.model = adbsat::Model::Sentman;
auto result = solver.compute(p, {-1,0,0}); // device kernel + synchronized reduction
```

The next integration step should bind this library to Python (nanobind/pybind11)
and compare every supported model against fixtures generated by the original
NumPy implementation before replacing a production campaign path.
